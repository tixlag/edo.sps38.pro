## Экран кадровика

Четыре колонки: Сотрудник, Документы, Что требуется, Действие. Дата и объект находятся в раскрываемых заголовках. ФИО — обычный текст; одна кнопка открывает существующую карточку/проверку. Поиск по коду 1С сохранён, отдельная колонка идентификатора убрана. Колонки участия, доставки ERP, локального завершения, неизвестного кадрового статуса 1С и технического внимания убраны.

Текущие заезды по умолчанию охватывают все даты: активные участия не скрываются из-за произвольной календарной границы. Архив начинается с явно отображаемого последнего месяца; Все даты снимает ограничение. Для групп и участников доступны предыдущая и следующая страницы; стеки курсоров входят в проверяемое URL-состояние. Выбранное участие и архивный контекст сохраняются при открытии документа и возврате. Документы в архивной строке относятся к текущей карточке, а не к историческому снимку комплекта.

## Единственный расчёт комплекта

Backend использует существующий ERP-каталог, stage rules, должность, объект, гражданство и исключения пола. SQL-предикат повторяет `requiredApplicable` для фильтрации до пагинации; соответствие проверяется тестами. Каждый тип считается один раз, даже если входит в несколько этапов. Дополнительные документы не увеличивают знаменатель обязательных.

`requirements` содержит известность и количества required/present/accepted/review/returned/missing/processing, completed и nextAction. При неизвестном составе количества nullable; пустой/устаревший каталог, неполные данные применимости и конфликт не доказывают завершение. Доступная проверка (`reviewAvailable`) независима от известности знаменателя.

Принятыми считаются обязательные документы с допустимой текущей принятой версией либо разрешённые ранее подтверждённые документы по существующим правилам ИГ: CONFIRMED, originalAvailable, originalVerified, usablePreviousUids, срок и isInvalid, запрет старых migration/patent. Переиспользование не является новой политикой обязательности. Для ранее подтверждённого проверенного оригинала `expiresAt = NULL` не блокирует зачёт: `isPreviousDocumentValid` получает отдельное доказательство сохранённого `CONFIRMED`; одного `knownValid` недостаточно. Остальные проверки оригинала, недействительности и запрет старых migration/patent сохранены. `usablePreviousUids` и расчёт реестра уже допускают NULL при подтверждённом оригинале.

Принятие комплекта и подтверждённая передача в 1С остаются разными фактами. Никакого статуса «Полностью оформлен» из них не выводится. Технические DTO остаются для подробностей/совместимости, но не образуют кадровые колонки.

## Матрица следующего действия

| Ситуация | Что требуется | Кнопка |
| --- | --- | --- |
| Нет связанной карточки | Не найдена карточка сотрудника | Нет неработающего действия |
| Есть реально ожидающая проверки текущая версия | Проверить N документов, даже при missing/returned | Проверить |
| Есть возвращённые документы, проверять сейчас нечего | Ожидается исправление | Открыть карточку |
| Документы обрабатываются | Ожидается обработка документов | Открыть карточку |
| Есть обязательные отсутствующие документы | Ожидаются N документов | Открыть карточку |
| Обязательный комплект принят | Все обязательные документы приняты | Открыть карточку |
| Передача в 1С не удалась | Передача документов в 1С не подтверждена; не подавляет доступную проверку | По доступному действию |
| Требования неизвестны или конфликтны | Готовность не определена / требуется уточнение | Открыть доступную карточку |

Кадровику не предлагается самостоятельно исправлять интеграцию или загружать документы за сотрудника. Неизвестная полнота не скрывает достоверно известную работу по проверке.
