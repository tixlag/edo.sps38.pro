# Разметка документов в ЭДО

## Выпуск и включение

Изменения относятся только к ЭДО: ERP и ЛК не требуют доработок. Перед запуском
новой версии API применить миграции `0018_document_annotations` и `0019_annotation_dataset_catalog` обычным способом
через `pnpm db:migrate`. Она добавляет таблицы разметки и действия аудита;
существующие документы не преобразуются. Развёртывание и изменение режима OCR
в эту задачу не входят.

При открытии «Списки полей» администратором обновляется справочник типов из 1С
и идемпотентно создаются опубликованные базовые списки для 29 известных типов
(31 вариант: отдельно паспорта RU/UZ и два носителя СНИЛС). Новые типы из 1С
появляются без настроенного списка; администратор создаёт их варианты и поля.
Новых фоновых заданий нет. Существующие списки, включая черновики, не заменяются.
Для отдельной инициализации после синхронизации каталога: `pnpm annotations:bootstrap`.
Команда проверяет базу `edo`, пишет изменения и аудит атомарно, без запуска OCR,
потребителей очередей и приложения целиком.

## Доступы и дашборд

- `20002` — проверка РУ; `20011` — ИГ; `20009` — обе группы и администрирование.
- Проверяющие работают по всем объектам, включая документы без объекта;
  `20007`/`20008` для этого не требуются. Группы определяются существующим правилом
  ЭДО: наличие чата или гражданство `ru` означает РУ.
- Самостоятельные права аудита сохраняют ограничения объектов. Сочетание аудита
  с проверкой не расширяет аудит чужой группы на все объекты. Аудит не разрешает
  изменение документов или разметки.
- Техническая диагностика доступна только `20009`. Рабочие OCR-наблюдения и области
  по-прежнему требуют `20010`; ручная разметка доступна без этого права.

Дашборд считает кандидатов и документы приёмки. Фильтры отдела и менеджера
сохраняются в URL и передаются в очередь документов. Возвраты в показателях —
текущий статус, историческая вкладка возвратов остаётся отдельной выборкой.
Недельные поступления считаются по отправленным версиям, включая повторные
подачи, за Пн–Вс UTC. Менеджеры берутся из сохранённого профиля кандидата;
совпадение имени не объединяет разные `code1c`.

## Настройка списков полей

Администратор выбирает тип из 1С, вариант документа и версию списка. Подписи
русские; технические коды полей назначаются автоматически и сохраняются при
переименовании. Поля можно выбрать из готовых списков или добавить по русскому
названию. Необязательная связь с реквизитом ERP выбирается отдельно и не определяет
состав разметки. Базовые физические поля описаны в `annotation-presets.ts` независимо
от `document_type_fields` и действующих распознавателей.

Вариант определяется оригиналом документа, а не гражданством владельца. Поле
`profile` в API каталога сохранено как технический код варианта (строка до 64 знаков);
оно больше не ограничено RU/UZ/OTHER. `sources.profile` остаётся прежней подсказкой
о гражданстве и не разрешает выбор каталога. Сервер проверяет тип документа и
последнюю опубликованную версию выбранного варианта. Опубликованные списки
неизменяемы; работа хранит снимок своей схемы.

Разделы обозначают смысловые страницы и повторяемые блоки. У паспорта РФ основной
разворот — страницы 2–3, штампы регистрации — страницы 5–12; эти номера не являются
индексами загруженного PDF. Разметчик привязывает раздел к одному или нескольким
сканам, а на одном скане может быть несколько разделов. Для повторов создаются
отдельные экземпляры блока. «Страница не загружена» отличается от отсутствия
раздела/поля в просмотренном документе.

Состав исходных шаблонов сверяется с публичными образцами: [паспорт РФ](https://eec.eaeunion.org/upload/medialibrary/58d/docs.pdf),
[паспорт UZ](https://www.consilium.europa.eu/prado/en/UZB-AO-02001/index.html),
[миграционная карта](https://eec.eaeunion.org/upload/files/paos/library/pr_spreads.pdf),
[НАКС](https://naks.ru/media/nts_protocols/Protokol_NTS39upd.pdf).
Шаблоны можно расширять для форм разных лет; отсутствующие реквизиты отмечаются
явно по оригиналу. Паспортная ID-карта UZ в начальные шаблоны не входит.

## Проверка и приёмка работы

Проверяющий открывает вкладку «Разметка строк», выбирает вариант документа и берёт работу.
Галочки участия и серверного требования включать участие больше нет.
Для каждого поля нужна общая область (контур или рамка), для каждой визуальной
строки — отдельная поворачиваемая рамка и точный текст. Поддерживаются фото,
подписи, печати и машинные коды без обязательной транскрипции. У нечитаемого
текстового поля сохраняется контур для сегментации, но не создаётся пример OCR.
У каждой области хранится `orientationDeg`: 0 — верх исходного изображения,
положительное направление — по часовой стрелке, диапазон [0, 360). Маркер «Верх»
и разворот на 180° сохраняют различие верха и низа независимо от формы контура.
У строк порядок вершин — верхний левый, верхний правый, нижний правый, нижний
левый в собственном направлении чтения; пересортировка по экранным координатам
не допускается. Написание сохраняется как на изображении, независимо от нормализованных
реквизитов. Отсутствующие и нечитаемые поля отмечаются явно.

Частичную работу можно сохранить черновиком. Отправка возможна после ответа на
все поля присутствующих экземпляров разделов; состояния остальных разделов
указываются отдельно. Администратор принимает работу или возвращает с комментарием.
Система сохраняет автора, редакции, строки и решения аудита; денежные начисления
не рассчитываются.

Разметка не изменяет реквизиты, состояние документа или отправку в ERP. Её можно
завершить после подтверждения документа. Ранее начатую работу над сохранённой
старой подтверждённой версией можно продолжить по ссылке версии в проверке.
Исторический просмотр из журнала остаётся только для чтения; новую работу над
исторической версией начать нельзя.

При удалении оригинала или незавершённой загрузке просмотр источника, отправка и
приёмка разметки блокируются; сохранённые сведения и черновик остаются видны.
Политика удаления возвращённых оригиналов не меняется. При конфликте редакций
локальные правки сохраняются; кнопка обновления сведений получает актуальное
состояние, после чего можно явно сбросить черновик до сохранённой редакции.

## Экспорт для обучения OCR

Операторский экспорт работает отдельно от production API и формирует выборку
только из принятых неизменяемых редакций. Инструкция установки, команды,
ограничения и форматы: [tools/ocr-export](../../tools/ocr-export/README.md).
Автоматического дообучения нет. Приватные документы, вырезки, подписи и результаты
экспорта не добавляются в Git.
