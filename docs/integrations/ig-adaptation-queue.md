# Очередь ИГ по допуску к адаптации

1С передаёт `operationId` вместе с каждым сотрудником в запросе допуска к «7 шагам». Сервис surveys сохраняет допуск и событие для ЭДО в одной транзакции. ЭДО читает неподтверждённые события и подтверждает их только после записи оформления и аудита. Повтор операции безопасен; события, которые не удалось обработать, остаются для повторной попытки.

В surveys необходимо применить миграцию `20261103100000_edo_adaptation_grant_events` и задать отдельный секрет `EDO_ADAPTATION_SYNC_TOKEN`. В ЭДО применить миграцию `20261103150000_ig_employment_cycles` и настроить `EDO_ADAPTATION_SYNC_ENABLED=true`, `EDO_ADAPTATION_EVENTS_URL` на `.../surveys-service/api/internal/edo/adaptation-grant-events` и тот же `EDO_ADAPTATION_SYNC_TOKEN`. В production адрес должен использовать HTTPS. Без этих настроек синхронизация отключена.

В тестовой базе 1С команда «Отправить в ЛК» не использует производственный `lk.sps38.pro`: полный адрес тестового endpoint `.../surveys-service/api/adaptation/access-grants` задаётся в `АдресСервера` подключения `HTTP_OUT_TOKEN_06`, а секрет `adaptation` должен соответствовать тестовому surveys. Адрес должен быть доступен **серверу 1С**, а не только браузеру разработчика. Если настройка отсутствует или указывает на производственный ЛК, отправка из тестовой базы останавливается.

Существующие допуски не импортируются автоматически. Для проверки нужны новые отправки на «7 шагов»; тестовые физлица и данные в 1С создаёт пользователь. До обновления и настройки всех трёх компонентов сквозной сценарий недоступен. События хранятся в surveys до подтверждения ЭДО; ошибки интеграции видны в журнале API ЭДО без содержимого запросов и секретов.
