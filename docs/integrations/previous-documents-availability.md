# Прежние документы в текущем оформлении

В карточке кандидата и списке выбранного этапа прежний оригинал показывается рядом с текущими документами. Backend возвращает `CandidateDetailsDto.previousDocuments`: только применимые к выбранному этапу виды без отправленного текущего комплекта. Это отдельный источник; новая загрузка или фиктивный документ `APPROVED` не создаются.

Статусы представления:

| API | Интерфейс | Учёт в прогрессе |
|---|---|---|
| `REUSED` | Зачтён ранее, с прошлого приёма/заезда | Да |
| `EXPIRED` | Нужна замена: срок действия истёк | Нет |
| `REPLACE_REQUIRED` | Для текущего оформления нужен новый документ | Нет |
| `REQUIRES_REVIEW` | Проверить актуальность | Нет |
| `ORIGINAL_UNAVAILABLE` | Оригинал недоступен | Нет |

Для зачёта требуется подтверждённый прежний источник (`CONFIRMED`), доступный оригинал, отсутствие отметки недействительности и истёкшего срока. Автоматическое подтверждение выполняет существующая синхронизация прежних документов с аудитом. Неизвестная действительность не превращается в подтверждение из-за интерфейса. Отсутствие даты окончания не подписывается как «бессрочный». `recordedAt` — дата записи источника, не вычисленная дата прошлого заезда.

Для ИГ миграционная карта и патент сохраняют требование нового документа для заезда. Действующий прежний оригинал учитывается для РФ и ИГ; истечение срока перепроверяется при чтении прогресса и при завершении оформления. Отправленный текущий комплект имеет приоритет, в том числе когда он на проверке или возвращён. Неотправленный технический `DRAFT` не скрывает пригодный прежний источник и не блокирует его зачёт.

Один прежний оригинал выбранного вида показывается в основной строке, предпочтение отдаётся пригодному. Все версии остаются в «Истории документов». Кнопка оригинала использует существующий защищённый endpoint; смена результата проверки обновляет карточку, этапы и очереди. Строка прежнего документа заменяет противоречивую подпись «Не загружен», но не снимает серверное требование замены непригодного документа.

Проверки: принадлежность выбранному этапу, РФ/ИГ, просрочка, недействительность, отсутствие оригинала, неизвестная актуальность, приоритет новой отправки, неотправленный черновик, отсутствие двойного зачёта и согласованность общего/этапного прогресса. Контракт дополнен через DTO → OpenAPI → сгенерированный клиент. Изменение не требует миграции БД.
