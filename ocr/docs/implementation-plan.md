# План подготовки монорепозитория

Согласовано: модульный UZ, два отдельных API и окружения, новый Git, веса отдельным архивом без LFS. Исходные проекты и службы сохраняются.

1. Перенести текущие исходники, сохранить происхождение и контракты.
2. Сделать пути переносимыми, включить миграционные карты, закрепить зависимости и PaddleOCR.
3. Подготовить архив моделей, манифест SHA-256 и проверяемую установку.
4. Описать запуск, добавить CI, AGENTS и бэклог объединения API.
5. Проверить контракты, архив и реальный inference в чистой копии.

Решение: новый каталог является согласованным изолированным рабочим пространством; worktree старых репозиториев не создаётся, поскольку он перенёс бы их историю и незафиксированные изменения пришлось бы обрабатывать отдельно.
