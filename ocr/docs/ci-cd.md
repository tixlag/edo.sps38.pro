# CI/CD OCR на рабочий компьютер

Входная конфигурация проекта остаётся `edo.yml@webdevs/ci-templates`. Она подключает `ocr/.gitlab-ci.yml` именно из коммита pipeline, с проверкой существования файла в проекте ЭДО. Это важно: include:local во внешнем шаблоне искал бы файл в ci-templates.

Автоматические задания `ocr-validate` и `ocr-deploy-pc` создаются только при push в защищённую ветку `main` с изменениями `ocr/**/*`. Runner: `deploy-ocr-pc`, тег `deploy-ocr-pc`, shell/bash, пользователь заданий `neuro`, `concurrent=1`. В GitLab у runner должны быть выключены Run untagged jobs и включён Protected. Не назначайте этот runner другим проектам.

`ocr-validate` выполняет весь набор OCR-тестов и проверяет Git index. Задание deploy зависит от его успеха, имеет resource_group `edo-ocr-pc` и не прерывается автоматически новым push. После локального lock скрипт дополнительно сравнивает дерево ocr/ с актуальным main до и после подготовки. Если новый commit изменил только ЭДО, предыдущее OCR-задание всё равно разворачивается; если OCR уже изменился, устаревшее задание пропускается.

## Каталоги

Управляемый runtime: `/home/neuro/.local/share/edo-ocr`.

- `releases/<полный SHA>` — только закоммиченный компонент OCR из git archive; рабочие изменения агента не копируются.
- `current` — атомарная ссылка на активную версию.
- `shared/models` — частный установленный комплект моделей.
- `shared/venvs` — отдельные окружения RU/UZ по хешу requirements.lock и установщика; при изменении зависимостей создаётся новое окружение.
- `shared/vendor` — закреплённый PaddleOCR по хешу setup/patch.
- `shared/glm` — Compose/Dockerfile по хешу содержимого. Образ GLM имеет отдельный тег по хешу Dockerfile; code-only push не пересобирает образ.
- `shared/config/{uz,ru}.env` — необязательные частные настройки, не копируемые из Git.
- `shared/var` — журналы/частные результаты, сохраняемые между релизами.
- `deployed.json` — SHA последнего успешного деплоя и URL pipeline.

Все каталоги runtime получены из монорепозитория. Старые RecognizeUZ/DocRecognizer и промежуточный monorepo-export не являются источниками импортов. Checkout разработчика `edo-integration` не обновляется заданиями CI.

Модели проверяются по манифесту до остановки служб. Если push требует новых моделей, сначала установите соответствующий частный архив в shared/models; иначе job завершится до переключения. Установщик окружений поддерживает SERVICE_VENV. На текущей машине OCR_WHEELHOUSE указывает на `/home/neuro/.cache/edo-ocr/wheels` с оригинальными wheels из pip cache; добавление новых зависимостей требует доступных точных wheels либо online-установки без этой переменной. Pip cache не очищайте, пока wheelhouse использует его файлы.

## Переключение и откат

После подготовки версии скрипт останавливает обе Python-службы, меняет current, применяет конфигурацию GLM и запускает службы. Он ждёт `/health` UZ со всеми моделями, OpenAPI РФ с `/parse` и доступной модели GLM. Затем выполняются реальные HTTP-запросы для всех трёх типов из частных `shared/var/regression/{uz.jpg,migration.png,ru.pdf}`; РФ должен вернуть не менее шести непустых полей, чтобы проверялся и ленивый запуск моделей. Значения и входные документы в CI log не выводятся. При ошибке возвращает previous current, конфигурацию GLM и службы; job остаётся красным. SIGTERM/SIGINT превращаются в исключение для выполнения отката, включая частичную ошибку остановки служб. SIGKILL/выключение питания не позволяют выполнить программный откат. Неудача самого отката также явно завершает job ошибкой. Модельные файлы, частная конфигурация и старые окружения автоматически не заменяются.

Только root-owned `/usr/local/sbin/edo-ocr-systemctl` разрешён через sudo без пароля: он принимает ровно start/stop/restart и управляет только recognize-uz.service и recognize-ru.service. Службы запускают Python от neuro, не от root. Runner использует существующий Docker-доступ пользователя neuro для GLM.

Начальная установка runner и unit-файлов: `sudo python3 ocr/deploy/runner/install_host.py --user neuro` после подготовки моделей, окружений и current. Она переносит зарегистрированный runner из пользовательского конфига в используемый системной службой config.toml, сохраняет закрытую резервную копию, задаёт MODELS_ROOT и устанавливает ограниченную sudo-команду. Сами API установщик не перезапускает.

Начальная подготовка до изменения unit-файлов:

1. Установить частные модели в shared/models, закреплённый vendor и три проверочных входа в shared/var/regression (они не публикуются).
2. Выполнить `python3 ocr/scripts/deploy_pc.py --bootstrap --prepare-only` из закоммиченной проверенной версии. При offline-установке передать OCR_WHEELHOUSE. Будут созданы complete release.json, окружения и конфигурация GLM с точным проверенным локальным образом.
3. Проверить подготовленный релиз на временных портах 18000/18001 со всеми тремя частными документами; передать MODELS_ROOT=shared/models. После успешной проверки остановить тестовые процессы, установить current на этот релиз и записать `baseline-verified.json` с его полным commit и `real_inference_verified: true`.
4. Только после этого выполнить root install_host.py. Установщик проверяет baseline и отказывается изменять конфигурацию при неполной или непроверенной версии. Действующие процессы ещё не перезапускаются.
5. Выполнить `python3 ocr/scripts/deploy_pc.py --bootstrap` для переключения и проверки рабочих портов. Для отката уже есть полный проверенный baseline current. После первого успешного деплоя подтверждением baseline служит deployed.json.

Bootstrap запрещён в GitLab CI; для будущих обновлений используется только защищённая main. Изменение Dockerfile сначала собирает новый образ до остановки работающих API.

После деплоя можно проверить:

```bash
cat /home/neuro/.local/share/edo-ocr/deployed.json
systemctl status recognize-uz.service recognize-ru.service --no-pager
curl --fail http://10.10.5.184:8000/health
curl --fail http://10.10.5.184:8001/docs
```

LAN и клиенты корпоративного VPN с маршрутом в `10.10.0.0/21` используют один адрес: `10.10.5.184`. UZ/миграционная карта — POST :8000/recognize, РФ — POST :8001/parse?doc_type=passport_ru. Доступ из конкретного VPN-клиента проверяется с самого клиента; VPN и маршрутизатор должны разрешать эту подсеть. Адрес хоста сейчас получен по DHCP; для постоянного URL закрепите его DHCP lease на маршрутизаторе.

Существующие build/API/web и ручной deploy-production ЭДО сохранены. Настройка OCR не запускает deploy-production, LK sync или миграции БД. Отдельный известный риск генерации production .env ЭДО остаётся описан в корневом AGENTS.md и не относится к локальным OCR-службам.

Справка по контексту include и правилам: https://docs.gitlab.com/ci/yaml/includes/ и https://docs.gitlab.com/ci/yaml/#rulesexistsproject.

Login shell runner читает `.bash_logout` пользователя. У стандартного Ubuntu clear_console возвращал exit 1 без терминала: установщик ограничивает этот блок проверками `-t 0` и `-t 1`, сохраняя поведение интерактивного терминала. Исходный файл сохраняется в закрытой резервной копии.
