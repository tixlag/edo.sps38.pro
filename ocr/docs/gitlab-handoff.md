# Передача OCR в составе ЭДО

Исходники находятся в `ocr/` существующего репозитория `webdevs/edo.sps38.pro`, с его историей и инструкциями. Вложенный Git отсутствует. Происхождение автономной сборки и её коммит записаны в `provenance.json`.

После получения ветки перейдите в `ocr/`, прочитайте `AGENTS.md` и README. Установите отдельные Python-окружения и частный архив моделей по инструкции. Файлы моделей, архивы, документы и окружения не входят в Git; не переносите их через `git add -f`.

Архив `recognizeuz-models-2026-10-20.tar.gz` и `.sha256` передаются отдельно через частное хранилище. Установщик проверяет манифест SHA-256.

GitLab CI управляется внешним `ci-templates/edo.yml`; для OCR подготовлен `ocr/.gitlab-ci.yml`. Включение фрагмента требует изменения внешнего шаблона, который не входит в этот репозиторий. Автоматический запуск OCR-тестов пока не подключён.

Граница с ЭДО и следующие задачи: `../../docs/integrations/document-ocr-sources.md`. Фактическое подключение OCR к NestJS/очереди является отдельной задачей; текущие настройки ручной обработки документов сохраняются.
