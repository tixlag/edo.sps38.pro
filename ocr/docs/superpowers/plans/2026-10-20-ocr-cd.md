# OCR PC CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A protected main push changing ocr/ validates and deploys the exact commit to the OCR PC.

**Architecture:** Keep edo.yml@webdevs/ci-templates as the entry point and include the OCR jobs from the pipeline commit. Use the dedicated tagged shell runner, persistent private assets, immutable releases, a local deployment lock, readiness checks and rollback.

**Tech Stack:** GitLab CI, shell runner, Python 3.12, systemd, Docker Compose.

**Spec:** User request in this session; operator details in ../../ci-cd.md.

## Global Constraints

- Preserve ports 8000, 8001, 8083, API contracts, models and fallback behavior.
- Deploy only webdevs/edo.sps38.pro, protected main, push events, changes under ocr/.
- Keep models, environments, credentials, private documents and inference output out of Git.
- Preserve the existing manual EDO production deploy; no GitHub Actions/e2e.

## Review Focus

- A broken release must restore the previous running release and fail the job.
- Concurrent/outdated jobs must not overwrite a newer main commit.
- Private files and uncommitted developer changes must not enter releases.
- Code-only updates must preserve dependency caches and GLM image/configuration.
- Registration in user config must actually reach the system runner service.
