# Проверки переноса — 2026-10-20

## Подтверждено

- 18 автоматических тестов проходят: переносимые настройки, включение миграционной карты, сигнатуры API РФ/UZ, реальные HTTP-обработчики UZ с заменой inference на его границе, установка/проверка/повторная упаковка моделей, повреждённые и неполные архивы, traversal и ссылки.
- Отдельный архив содержит 16 файлов; проверены размеры и SHA-256, установка архива в чистую копию и повторная проверка всего комплекта.
- Два новых окружения Python 3.12 установлены из исходных кэшированных wheels по закреплённым снимкам. Старые `site-packages` не подключаются. Ненужный CPU Paddle исключён.
- Все пять моделей UZ загружаются; `/health` подтверждает их наличие. Реальные паспорта UZ и миграционная карта обрабатываются через HTTP.
- РФ `/parse` возвращает заполненные данные паспорта. OpenAPI перенесённого РФ целиком совпадает с OpenAPI действующего сервиса на `8001`.
- Для проверенного паспорта UZ ответ совпадает с исходной модульной реализацией. В новых окружениях ответы UZ/миграционной карты совпали с ответами в исходных окружениях; данные полей РФ также совпали. Динамические пути и тайминги РФ не сравнивались как постоянные значения.
- UZ multipart и base64 дают одинаковый результат на одном изображении; debug и сохранение сегментов работают, создаётся manifest. PDF из двух страниц возвращает два документа.
- РФ принимает PDF; `/parse-id-birthday` возвращает HTTP 200 со своей прежней структурой ответа.
- Исходные службы не переключались: РФ продолжает работать на `8001`, GLM — на `8083`. Тестовые процессы используют `18000`–`18002` и останавливаются после проверки.
- Состав Git проверяется `scripts/check_repository.py`: запрещённых артефактов и обнаруживаемых этим скриптом секретов нет. Старые истории Git и `.env` не импортированы.

- Проверена чистая копия в другом каталоге: модели установлены из архива, отдельные среды созданы заново из wheelhouse, закреплённый PaddleOCR подготовлен локально. Все три типа распознаны через HTTP; ответы UZ/миграционной карты и поля РФ совпали с основной сборкой. Никакие runtime-модули или модели не подключаются из исходных RecognizeUZ/DocRecognizer.

## Перенос в репозиторий ЭДО

Компонент размещён в `ocr/` без вложенного Git-репозитория. Исполняемые файлы `services/` совпадают с проверенной самостоятельной сборкой; пути вычисляются относительно компонента. Настройки приложения ЭДО, его OCR provider и работающие службы не менялись.

Для вложенного компонента адаптирована проверка Git index и добавлены три regression-теста: чтение файлов именно из `ocr/`, обнаружение секрета внутри компонента и сохранение работы в самостоятельном репозитории. Всего проходят 21 тест. Проверка индекса подтверждает отсутствие запрещённых артефактов в 149 файлах OCR; `git diff --cached --check` не сообщает ошибок.

Фрагмент OCR CI подготовлен, но не включён во внешний `ci-templates/edo.yml`. Проверки выполнялись локально; pipeline ЭДО и повторное развёртывание не запускались.

## Ограничения и существующие особенности

Это проверки работоспособности и отсутствия наблюдённых регрессий при переносе, не измерение точности на полном размеченном наборе.

Из четырёх локальных тестовых изображений UZ три вернули документы, одно получило HTTP 400 из-за проверки ориентации/набора полей. Тот же отказ подтверждён на исходной модульной реализации; пороги не ослаблялись.

В некоторых датах UZ остаются пробелы вместо ожидаемых разделителей. На проверенной миграционной карте некоторые поля, включая дату рождения и номер паспорта, распознаны некорректно. Эти результаты воспроизводятся в исходном окружении. Алгоритмы, модели и правила исправления при переносе не менялись, кроме согласованного включения миграционной карты. Качество и обработка клеток ФИО требуют частного regression-набора и отдельной работы.

`pip check` сообщает существующие несовместимости требований Torch/Paddle к CUDA-библиотекам. Поэтому установка воспроизводит снимок с `--no-deps`; согласование зависимостей вынесено в бэклог. Версии и ограничения — в `installation.md`.

Чистая загрузка wheels с Paddle CDN не подтверждена: в текущей среде DNS этого хранилища недоступен. Для фактической установки использованы локально кэшированные оригинальные wheels. Для автономной установки UZ также предварительно перенесён закреплённый checkout PaddleOCR; wheelhouse не содержит его исходники.

GLM используется существующий. Новый Dockerfile закрепляет digest и commit Transformers действующего контейнера; новый контейнер не собирался и не разворачивался. GitLab CI подготовлен, но на GitLab ещё не запускался. Конфигурация конкретного внешнего прокси не переносилась.

## Повторение

```bash
.venv-test/bin/python -m unittest discover -s tests -v
python3 scripts/models.py verify
python3 scripts/check_repository.py
```

Реальный inference с частным документом:

```bash
python3 scripts/check_inference.py --url http://127.0.0.1:8000/recognize \
  --input /private/uz-passport.jpg --expect-type passport --output var/verification/uz.json
python3 scripts/check_inference.py --url http://127.0.0.1:8000/recognize \
  --input /private/migration-card.jpg --expect-type migration_card --output var/verification/migration.json
python3 scripts/check_inference.py --url http://127.0.0.1:8001/parse \
  --input /private/ru-passport.jpg --output var/verification/ru.json
```

Этот smoke-скрипт проверяет HTTP, наличие результата и ожидаемого типа; правильность значений полей нужно проверять отдельно по документу. Частные ответы, входные изображения и журналы остаются вне Git.
