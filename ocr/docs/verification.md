# Проверки переноса — 2026-10-20

## Подготовка самостоятельной сборки (до переключения служб)

- 18 автоматических тестов проходят: переносимые настройки, включение миграционной карты, сигнатуры API РФ/UZ, реальные HTTP-обработчики UZ с заменой inference на его границе, установка/проверка/повторная упаковка моделей, повреждённые и неполные архивы, traversal и ссылки.
- Отдельный архив содержит 16 файлов; проверены размеры и SHA-256, установка архива в чистую копию и повторная проверка всего комплекта.
- Два новых окружения Python 3.12 установлены из исходных кэшированных wheels по закреплённым снимкам. Старые `site-packages` не подключаются. Ненужный CPU Paddle исключён.
- Все пять моделей UZ загружаются; `/health` подтверждает их наличие. Реальные паспорта UZ и миграционная карта обрабатываются через HTTP.
- РФ `/parse` возвращает заполненные данные паспорта. OpenAPI перенесённого РФ целиком совпадает с OpenAPI действующего сервиса на `8001`.
- Для проверенного паспорта UZ ответ совпадает с исходной модульной реализацией. В новых окружениях ответы UZ/миграционной карты совпали с ответами в исходных окружениях; данные полей РФ также совпали. Динамические пути и тайминги РФ не сравнивались как постоянные значения.
- UZ multipart и base64 дают одинаковый результат на одном изображении; debug и сохранение сегментов работают, создаётся manifest. PDF из двух страниц возвращает два документа.
- РФ принимает PDF; `/parse-id-birthday` возвращает HTTP 200 со своей прежней структурой ответа.
- На этапе подготовки исходные службы не переключались. Проверки выполнялись на `18000`–`18002`; после них временные процессы остановлены. Последующее переключение на монорепозиторий описано ниже.
- Состав Git проверяется `scripts/check_repository.py`: запрещённых артефактов и обнаруживаемых этим скриптом секретов нет. Старые истории Git и `.env` не импортированы.

- Проверена чистая копия в другом каталоге: модели установлены из архива, отдельные среды созданы заново из wheelhouse, закреплённый PaddleOCR подготовлен локально. Все три типа распознаны через HTTP; ответы UZ/миграционной карты и поля РФ совпали с основной сборкой. Никакие runtime-модули или модели не подключаются из исходных RecognizeUZ/DocRecognizer.

## Перенос в репозиторий ЭДО

Компонент размещён в `ocr/` без вложенного Git-репозитория. Исполняемые файлы `services/` совпадают с проверенной самостоятельной сборкой; пути вычисляются относительно компонента. При первоначальном импорте настройки приложения ЭДО, его OCR provider и работающие службы не менялись.

Для вложенного компонента адаптирована проверка Git index и добавлены три regression-теста: чтение файлов именно из `ocr/`, обнаружение секрета внутри компонента и сохранение работы в самостоятельном репозитории. Всего проходят 21 тест. Проверка индекса подтверждает отсутствие запрещённых артефактов в 149 файлах OCR; `git diff --cached --check` не сообщает ошибок.

Фрагмент OCR CI подготовлен, но не включён во внешний `ci-templates/edo.yml`. Проверки выполнялись локально; pipeline и развёртывание Node-приложения ЭДО не запускались.

## Переключение рабочих OCR-служб на монорепозиторий

По указанию пользователя от 20.10.2026 единственным поддерживаемым источником и местом запуска стал `edo.sps38.pro/ocr`. В старых локальных проектах и промежуточном monorepo-export размещены уведомления legacy.

- В компоненте созданы два новых Python-окружения из закреплённых wheels, установлен и проверен комплект из 16 модельных файлов, размещён закреплённый PaddleOCR. Среды и импорты не ссылаются в прежние проекты.
- `recognize-uz.service` и `recognize-ru.service` активны, включены в автозагрузку и запускаются из `ocr/`. Прежняя `doc-recognizer.service` остановлена и замаскирована. Тестовые порты `18000`/`18001` освобождены.
- GLM пересоздан из того же проверенного образа под управлением `ocr/deploy/glm/compose.yaml`, Compose-проект `edo-ocr`. Старый контейнер остановлен, переименован с префиксом `legacy-` и имеет `restart=no`. Образ, модель и параметры inference не обновлялись. При начальном запуске GLM дважды перезапустился из-за инициализации GPU/NVML; затем успешно загрузился и прошёл inference. Сборка нового образа из Dockerfile не выполнялась.
- На рабочих портах `8000`/`8001` повторены реальные запросы: паспорт UZ и миграционная карта — по 11 полей в ответе, паспорт РФ из PDF — 10 непустых полей. Полные ответы UZ/миграционной карты и поля РФ совпали с сохранённой проверенной сборкой. Это подтверждает отсутствие наблюдённой регрессии, а не правильность каждого поля.
- Новый GLM вернул HTTP 200 на все 12 запросов `/v1/chat/completions` во время проверок. Все ветви fallback принудительно не перебирались.
- Из отдельного клиентского Docker-контейнера получен HTTP 200 по сетевому адресу `10.10.5.184` на `8000/health`, `8001/openapi.json` и `8083/v1/models`. Это проверка входящего доступа из другой сетевой namespace; физический второй компьютер в LAN не использовался.
- В тестовом окружении внутри монорепозитория проходят 21 тест. Резервные копии служебной конфигурации, входы и результаты сохранены в игнорируемом `var/`; в Git не включены.

Управление и порядок установки: `operations.md`. Автозагрузка проверена по состоянию systemd и restart policy Docker; перезагрузка всей машины не выполнялась.

## Автоматический CI/CD на рабочий компьютер

Внешний `edo.yml@webdevs/ci-templates` подключает OCR jobs из коммита pipeline. Runner #19 (`deploy-ocr-pc`) использует tag deploy-ocr-pc, protected-only, project lock и не принимает untagged jobs. Регистрация перенесена в системный config.toml, который читает работающая служба; задания исполняются от neuro.

Управляемый runtime — `/home/neuro/.local/share/edo-ocr/current`; checkout для разработки больше не является путём работающих служб. Перед изменением unit-файлов проверен полный baseline с независимыми окружениями на временных портах. MODELS_ROOT явно задан в systemd, модели и private regression inputs находятся в shared. Инструкция — `ci-cd.md`.

Подтверждён настоящий push pipeline [3650](https://glab.sps38.pro/webdevs/edo.sps38.pro/-/pipelines/3650): ocr-validate и ocr-deploy-pc завершились успешно; deployed.json содержит SHA c415e010dc8f52b2347366a1e55fb8293e080013 и URL этого pipeline. Все три типа документов прошли post-deploy HTTP inference. Build API/web также успешны, production deploy остался ручным и не запускался.

Первый запуск validate остановился на login-shell preparation из-за штатного clear_console в .bash_logout без терминала. Условие ограничено интерактивным терминалом; воспроизведение до исправления возвращало exit 1, после — exit 0. Повтор задания успешен.

Локально проходят 33 теста, включая откат при ошибке GLM/readiness/SIGTERM, восстановление после частичной остановки, запрет незащищённой/main-не-push ветки, исключение частных и незакоммиченных файлов, устаревшее OCR-задание с последующим не-OCR коммитом и повторную проверку частных входов для cached release. GitLab CI Lint принял объединённый шаблон без ошибок и предупреждений. Новая сборка GLM Dockerfile по-прежнему не выполнялась: используется точный проверенный образ, неизменный для code-only deploy.

## Ограничения и существующие особенности

Это проверки работоспособности и отсутствия наблюдённых регрессий при переносе, не измерение точности на полном размеченном наборе.

Из четырёх локальных тестовых изображений UZ три вернули документы, одно получило HTTP 400 из-за проверки ориентации/набора полей. Тот же отказ подтверждён на исходной модульной реализации; пороги не ослаблялись.

В некоторых датах UZ остаются пробелы вместо ожидаемых разделителей. На проверенной миграционной карте некоторые поля, включая дату рождения и номер паспорта, распознаны некорректно. Эти результаты воспроизводятся в исходном окружении. Алгоритмы, модели и правила исправления при переносе не менялись, кроме согласованного включения миграционной карты. Качество и обработка клеток ФИО требуют частного regression-набора и отдельной работы.

`pip check` сообщает существующие несовместимости требований Torch/Paddle к CUDA-библиотекам. Поэтому установка воспроизводит снимок с `--no-deps`; согласование зависимостей вынесено в бэклог. Версии и ограничения — в `installation.md`.

Чистая загрузка wheels с Paddle CDN не подтверждена: в текущей среде DNS этого хранилища недоступен. Для фактической установки использованы локально кэшированные оригинальные wheels. Для автономной установки UZ также предварительно перенесён закреплённый checkout PaddleOCR; wheelhouse не содержит его исходники.

GLM использует прежний проверенный образ; новый Dockerfile закрепляет его базовый digest и commit Transformers, но сборка Dockerfile не проверялась. Пересоздание контейнера из локального образа проверено при переключении выше. GitLab CI подготовлен, но на GitLab ещё не запускался. Конфигурация конкретного внешнего прокси не переносилась.

```bash

```

Реальный inference с частным документом:

```bash
python3 scripts/check_inference.py --url http://127.0.0.1:8000/recognize \
  --input /private/uz-passport.jpg --expect-type passport --output var/verification/uz.json
python3 scripts/check_inference.py --url http://127.0.0.1:8000/recognize \
  --input /private/migration-card.jpg --expect-type migration_card --output var/verification/migration.json
python3 scripts/check_inference.py --url http://127.0.0.1:8001/parse \
  --input /private/ru-passport.jpg --output var/verification/ru.json
```

Этот smoke-скрипт проверяет HTTP, наличие результата и ожидаемого типа; правильность значений полей нужно проверять отдельно по документу. Частные ответы, входные изображения и журналы остаются вне Git.
