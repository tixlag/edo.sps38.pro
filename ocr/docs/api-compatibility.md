# Совместимость API

| Сервис | Метод и путь | Вход |
|---|---|---|
| UZ | GET `/health` | состояние моделей |
| UZ | POST `/recognize` | multipart, несколько `files` |
| UZ | POST `/recognize-base64` | JSON `files: [{filename, content_base64}]` |
| РФ | POST `/parse` | multipart, несколько `files` |
| РФ | POST `/parse-id-birthday` | multipart, несколько `files` |

UZ сохраняет query/form параметры `debug`, `ocr_improve`, `save_segments`, query alias `dump_segments`. Для multipart значение form переопределяет query. Для base64 флаги query и body объединяются через OR. Поля и типы ответов сохраняются из модульной реализации. Пустой результат multipart возвращает HTTP 400 `Плохое качество документа`; base64 возвращает пустой список. Не менять это расхождение при уборке репозитория.

РФ сохраняет query `doc_type`, `ollama_model`, `ollama_url`, `dpi`, `ocr_engine`, `debug`, `async_proc`; `/parse` также принимает `no_llm`. Значения по умолчанию закреплены тестом сигнатур. Legacy параметры Ollama остаются в контракте; текущий fallback использует GLM из окружения. Заготовки `passport_uz` и `snils` в РФ не имеют рабочих путей моделей и не являются поддержкой этих документов. UZ обрабатывает отдельный сервис.

Сигнатуры исходных маршрутов сохранены в `tests/api_baseline.json`. В UZ включены миграционные карты, которые были выключены фильтром `ALLOWED_DOC_TYPES` в выбранной модульной версии. Обработка клеток ФИО остаётся в исходном режиме `replace`; это известное отличие от старого монолита.

Логи и debug-метаданные содержат пути к рабочим каталогам. После переноса эти пути указывают на новый проект. Произвольные тайминги, request ID и пути не должны сравниваться как постоянные значения в regression-проверках.
