# Инструкции для агента

Компонент находится в `ocr/` репозитория ЭДО. Все относительные пути и команды ниже отсчитываются от `ocr/`. Сначала прочитайте корневой `../AGENTS.md`.

Цель проекта — сохранить рабочее распознавание российского паспорта, паспорта UZ и миграционной карты.

Уточнение пользователя от 2026-10-20: на машине агента нет весов; локально не запускать OCR inference и Python OCR-тесты. OCR проверяется после деплоя через runner на `10.10.5.184`; окончательный результат сообщает пользователь. До его подтверждения не включать внешний OCR и не выполнять этап деплоя API/web ЭДО. Фактические порты проверены и согласованы: UZ/миграционная карта — 8000, РФ — 8001.

Единственный поддерживаемый источник и место запуска — `ocr/` этого монорепозитория. Прежние отдельные проекты `RecognizeUZ`, `DocRecognizer` и промежуточный `monorepo-export` имеют статус **legacy**: не исправляйте и не запускайте их. Рабочие изменения делайте только здесь. Порядок переключения и службы описаны в `docs/operations.md`.

Рабочий компьютер автоматически получает закоммиченную копию компонента из защищённой `main` при изменении `ocr/`. Управляемый runtime — `/home/neuro/.local/share/edo-ocr/current`; не редактируйте его вручную. Окружения, модели и частные проверочные документы находятся вне Git. CI/CD и откат: `docs/ci-cd.md`.

- `services/uz`: рабочая модульная реализация `recognizeuz`; разрешены `passport` и `migration_card`.
- `services/ru`: рабочий `doc_recognizer_universe.py`. Не заменяйте его файлами из `archive`.
- Среды и версии зависимостей сервисов различаются. Устанавливайте их отдельно по `docs/installation.md`.
- UZ: `0.0.0.0:8000`, `/recognize`, `/recognize-base64`, `/health`. РФ: `0.0.0.0:8001`, `/parse`, `/parse-id-birthday`. GLM: `127.0.0.1:8083/v1/chat/completions`.
- Сохраняйте параметры, значения по умолчанию, ответы и ошибки API. Объединение сервисов требует отдельной задачи из бэклога.
- Не обновляйте модели, словари, пороги OCR и библиотеки вместе с уборкой структуры. Для UZ расширяйте `DocumentSpec` и stages, а не общий pipeline условиями конкретных документов.
- Модели устанавливаются из отдельного архива: `python3 scripts/models.py install ARCHIVE`. Проверка: `python3 scripts/models.py verify`.
- В Git нельзя добавлять модели, архивы, `.env`, входные документы, персональные данные, датасеты, логи, результаты распознавания и обучения. Не выполняйте `git add -f` для игнорируемых файлов.
- Быстрая проверка: `.venv-test/bin/python -m unittest discover -s tests -v`. Создание среды описано в README.
- Тесты HTTP используют замену inference на границе pipeline и не доказывают качество OCR. Проверяйте реальные документы отдельно, результаты храните в игнорируемом `var/verification`.
- Для ручных проверок используйте временные порты, например `18000`/`18001`. Не останавливайте и не переключайте установленные службы без отдельного указания.
- Актуальные ограничения и результаты проверок: `docs/verification.md`. Происхождение: `docs/provenance.json`. План развития: `docs/backlog.md`.
