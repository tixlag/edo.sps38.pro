# Экспорт принятой разметки

Отдельный инструмент оператора на Node.js 22+. Он не входит в production Docker
ЭДО, не запускает OCR и не изменяет БД. Использует MariaDB `edo` и приватный S3
через существующий `StorageService`. Корневая `.env` загружается явно.

Установка на машине оператора из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm --filter @edo/api prisma:generate
pnpm --dir tools/ocr-export install --ignore-workspace --frozen-lockfile
```

Проверка без записи файлов (режим по умолчанию) и экспорт:

```sh
pnpm annotations:export -- --dry-run --limit=100
pnpm annotations:export -- --apply --limit=100 --out=.cache/ocr-exports/batch-001
pnpm annotations:export -- --apply --annotation-id=ID --out=.cache/ocr-exports/selected
```

Экспорт выбирает последнюю принятую редакцию каждой принятой работы. Для больших
объёмов используйте `--annotation-id` и отдельные каталоги; `--limit` ограничен 1000.
Каталог результата должен быть новым. Оригиналы сверяются по SHA-256, наличию
версии и файлов. `COMPLETE.json` означает полностью завершённую выгрузку.
Если маркер отсутствует, выгрузка неполная: исправьте причину и повторите в новый
каталог. Ошибка не отменяет приёмку разметки и не меняет документы.

Результат:

- `pages/`: PNG страниц после EXIF и PDF CropBox/Rotate, PDF 200 DPI;
- `lines/`: отдельный выровненный PNG для каждой читаемой строки;
- `labels.txt`: относительный путь, TAB, точный текст строки для PaddleOCR;
- `manifest.jsonl`: источник и хеши, версии схемы/разметки, координаты и порядок,
  подпись, хеш вырезки, профиль рендеринга и группа для разбиения выборки.
- `snapshots.jsonl`: полная принятая схема, ответы и метаданные источников, включая
  отсутствующие и нечитаемые поля; без ключей S3 и временных ссылок.

Параллельная запись в один каталог блокируется. Если процесс был принудительно
завершён и оставил `.export.lock`, повторите выгрузку в новый каталог.

Отметки «Нет в документе» и «Не читается» не создают обучающих примеров.
При разбиении train/validation/test используйте `splitGroup`: все документы,
версии и строки одного человека должны попадать в одну часть. Это поле объединяет
известный `code1c`, затем кандидата; при отсутствии связи остаётся документ.
Не распределяйте строки случайно. Перед обучением отдельно объедините известные
дубли кандидатов, для которых в ЭДО нет общего идентификатора.

Выгрузка содержит персональные данные. Храните её в закрытом месте; стандартный
путь `.cache/` исключён из Git. Не добавляйте результаты, документы и логи в репозиторий.
Ограничения: 40 Мп на страницу, 50 МиБ на исходный файл, 1000 работ за запуск;
CPU без Python/GPU. Прямоугольники ориентированные, перспективные четырёхугольники
не поддерживаются. Тесты на синтетических изображениях/PDF:

```sh
pnpm --dir tools/ocr-export test
```
